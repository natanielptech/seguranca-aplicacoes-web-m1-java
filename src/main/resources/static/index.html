MÓDULO 1 · LABORATÓRIO

Observe como a web funciona

Experimente requisições reais e acompanhe o caminho entre navegador e servidor.

Use apenas dados fictícios. A autenticação desta demonstração é local e não usa banco de dados.

O caminho de uma requisição

1

Navegador

Você interage com a página e inicia uma requisição.

2

HTTP / HTTPS

Método, URL, headers e, às vezes, body viajam até o servidor.

3

API

O servidor valida a entrada e responde com um status e JSON.

Experimente na prática

Abra o DevTools (F12), selecione Network e compare estes quatro exemplos de requisição e resposta.

Autenticação e perfis de acesso

As credenciais são enviadas em cada requisição usando HTTP Basic. Escolha um usuário para testar:

  • leitor / leitor123 — perfil LEITOR: consulta (GET).
  • admin / admin123 — perfil ADMIN: consulta (GET) e envio (POST).

A API responde 401 sem credenciais válidas e 403 quando o perfil não tem permissão.

Exemplo 1 · GET válido

Consulta um tema. O valor selecionado aparece como parâmetro na URL.

Exemplo 2 · POST válido

A mensagem vai no body JSON. Uma resposta 201 indica envio aceito, não armazenamento permanente.

POST /api/observacao
Content-Type: application/json

{"mensagem":"Olá, mundo!"}

Exemplo 3 · parâmetro inválido

O servidor valida o tema recebido e responde 400 quando ele não é permitido.

GET /api/observacao?tema=desconhecido

Resposta: 400 Bad Request

Exemplo 4 · método não permitido

A API aceita GET e POST. Para outro método, responde 405 e informa os métodos aceitos.

DELETE /api/observacao

Resposta: 405 Method Not Allowed
Allow: GET, POST
